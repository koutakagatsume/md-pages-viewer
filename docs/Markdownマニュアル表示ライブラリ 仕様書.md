# Markdownマニュアル表示ライブラリ 仕様書

Oct 30, 2026 · @Kota Kagatsume

## 1. 概要

FullCalendarのように、どのプロジェクトにも `<script>` 1行で組み込めるMarkdown表示ライブラリ `md-pages-viewer` を作る。マニュアルを主な用途とし、マニュアルに限らず階層のあるMarkdown文書全般に使える形で、受け取ったページデータからパンくず・サイドバー・ページ内目次・本文を描画する。

## 2. 現状

| 区分 | 内容 |
| --- | --- |
| 実装済み（活用するもの） | marked 18系（Markdown変換。MITライセンスと、John Gruber の Markdown のライセンス（BSD形式）。他パッケージへの依存なし）、DOMPurify 3系（HTMLのサニタイズ。MPL-2.0 または Apache-2.0）。どちらもnpmの公開パッケージ |
| 未実装（今回の対象） | ライブラリ本体、ビルド設定、デモページ、テスト、GitHub・npmへの公開。リポジトリも新規に作る |

| 項目 | 内容 |

| データの渡し方 | ページの配列を直接渡す、またはその配列をJSONで返すURLを渡す |

| ライブラリが担う範囲 | ブラウザ上の処理だけを担う。パンくず・サイドバー・ページ内目次・本文の描画、ページの検索、mdファイルの取得、画像・リンクのパス解決、HTMLのサニタイズ、URLへの現在ページの反映 |
| 利用側で実装するもの | データの保存（DBのテーブル・マイグレーション）、ページ一覧を返すAPI、ストレージへの保存とCORS設定、署名付きURLの発行、非公開の画像を返すAPI。ページ一覧は本書 4 の形式で返せば、DBの種類やテーブル構造は問わない |

| 既存ページへの影響 | 組み込み先のレイアウト・ナビ・CSSを崩さない。組み込み先のCSSのセレクタ（`h2` の指定やリセットCSSなど）は本ライブラリの中に効かない。組み込み先から引き継ぐ値は本書 5.8 のとおり |
| 見た目の調整 | 色・フォント・余白をCSS変数で上書きできる。部品ごとの見た目は組み込み先の `::part()` で、本文の見た目は組み込み先が渡すCSSで変えられる |
| 安全性 | 表示するHTMLはすべてサニタイズする |

## 4. データ形式

ページはフラットな配列で受け取り、`parentId` で階層を表す。URLで渡す場合、そのURLはこの配列そのものをJSONで返す。

| 項目 | 型 | 必須 | 内容 |
| --- | --- | --- | --- |
| id | string / number | 必須 | ページの一意なID |
| parentId | string / number / null | 必須 | 親ページのID。最上位はnull |
| title | string | 必須 | パンくず・サイドバーに表示する名前。HTMLとして解釈せず文字列のまま表示する |
| description | string | 任意 | 子ページ一覧と検索の結果に出す説明文。HTMLとして解釈せず文字列のまま表示する。前後の空白は除き、空白だけの場合はないものとして扱う |
| thumbnail | string | 任意 | 子ページ一覧をカードの形にしたとき、そのページのカードの上に出す画像のパスまたはURL（本書 5.4）。そのページの本文の画像と同じ規則で解決する（本書 5.3）。前後の空白は除き、空白だけの場合はないものとして扱う |
| md | string | 任意 | 本文のMarkdown文字列 |
| src | string | 任意 | mdファイルのURL。空文字・空白だけの場合は `src` がないものとして扱う |
| order | number | 任意 | 同じ階層内の並び順（小さい順）。同じ値のページは配列の順に並べる。未指定のページは、同じ階層で `order` を指定したページの後に配列の順に並べる |

`md` も `src` もないページは、本文の代わりに子ページの一覧を表示する（本書 5.4）。カテゴリのように、子ページをまとめる親ページに使う。

データの例：

| id | parentId | title | 本文の指定 | order |
| --- | --- | --- | --- | --- |
| intro | null | はじめに | md：Markdown文字列 | 1 |
| login | intro | ログイン方法 | src：`https://xxx.s3.amazonaws.com/manual/login.md` | 1 |
| faq | null | FAQ | src：`/storage/manual/faq.md` | 2 |
| guide | null | 操作ガイド | なし（子ページの一覧を表示） | 3 |

データが想定と異なる場合の扱い：

| 状況 | 扱い |
| --- | --- |
| `id` または `title` がない | そのページを使わず、コンソールに警告を出す |
| `parentId` の項目がない | null と同じく最上位のページとして扱う |
| `md` と `src` が両方ある | `md` を表示する |
| `md` も `src` もなく、子ページもない | 本文が空のページとして表示し、コンソールに警告を出す |
| `id` が重複している | 配列で先に出てくるページを使い、後のページは無視してコンソールに警告を出す |
| `parentId` の親が存在しない | 最上位のページとして扱い、コンソールに警告を出す |
| `parentId` が循環している | 循環に含まれるページのうち、配列で最初に出てくるページを最上位として扱い、コンソールに警告を出す |
| IDの型 | 文字列に変換して比較する（`1` と `"1"`、URLの `?page=1` は同じページを指す） |

## 5. 機能要件

### 5.1 最初に開くページ

上から順に判定し、最初に当てはまるページを開く。

1. 組み込み先ページのURLに `?page=ID` がある（本書 5.5）
2. `currentId` が指定されている
3. 最上位のページのうち、並び順（本書 4）で先頭のページ

1・2のIDに当たるページが存在しない場合は、本文の場所に「ページが見つかりません」と表示する。パンくずは表示せず、サイドバーはどのページも強調しない。

ページが1件もない場合は、ツールバー（パンくず・検索欄を含む）・サイドバー・目次を表示せず、本文の場所に「ページがありません」と表示する。

### 5.2 本文の取得

`md` があればそれを表示する。`src` があれば、そのページを開いた時点でURLから取得して表示する。本文は開いたページの分だけ取得する。

取得した本文はページのIDごとに保持し、同じページを開き直したときは取得しない。取得の途中で別のページへ移った場合も、取得できた本文は保持する。取得が終わる前に同じページを開き直した場合は、取得中の結果を待ち、もう一度取得しない。保持した本文は、画面を再読み込みしたとき、`pages` または `fetch` を変更したとき（本書 5.6）に捨てる。署名付きURLの期限切れに対応して一覧を取得し直したとき（下の表）は捨てない。

| 保存場所 | 利用側で必要な対応 |
| --- | --- |
| S3（公開バケット） | バケットにCORS設定（組み込み先のオリジンからのGETを許可）を追加する |
| S3（非公開バケット） | バケットにCORS設定（組み込み先のオリジンからのGETを許可）を追加する。サーバー側で署名付きURLを発行し、`src` に渡す。期限があるため、ページ一覧を返すたびに発行する |
| サーバーのストレージ | ブラウザからアクセスできるURLにする（Laravelなら `storage:link`、または認証付きルート経由） |

HTTPステータスが200番台以外の応答と、通信エラーを取得の失敗とする。ページ一覧は、応答が配列のJSONでない場合も失敗とする。

取得中と失敗時の表示：

| 状況 | 表示・動作 |
| --- | --- |
| ページ一覧の取得中 | ライブラリの表示領域全体に読み込み中の表示を出す |
| ページ一覧の取得に失敗 | 表示領域全体に「読み込めませんでした」と再読み込みボタンを出す。ボタンで一覧を取得し直す |
| 本文の取得中 | 本文の場所に読み込み中の表示を出す。パンくず・サイドバーは先に切り替える |
| 本文の取得に失敗（`pages` をURLで渡している場合） | ページ一覧を取得し直し、新しい `src` で本文を1回だけ取得し直す。署名付きURLの期限切れに対応するため。取得し直している間は本文の場所に読み込み中の表示を出し、サイドバー・パンくずはそのまま表示する。取得し直した一覧でサイドバー・パンくずも描画し直し、そのページが一覧からなくなっていた場合は「ページが見つかりません」と表示する |
| 本文の取得に失敗（上記で一覧または本文の取得し直しに失敗、または `pages` を配列で渡している場合） | 本文の場所に「読み込めませんでした」と再読み込みボタンを出す。ボタンを押すと、この表の「本文の取得中」から同じ流れで取得し直す |

ページ一覧と本文の取得には `fetch` オプションの関数を使う。未指定時はブラウザの `fetch` を使う。別オリジンのAPIでCookieや認証ヘッダーを付ける場合は、利用側がこの関数で付ける。組み込み先ページと同じオリジン（スキーム・ホスト・ポートが同じ）のAPIはCookieが自動で付くため指定不要。

### 5.3 画像とリンクのパス

Markdown内の画像は次の順で表示用のURLを決める。

| 条件 | 表示に使うURL |
| --- | --- |
| `imageResolver` を指定している | すべての画像について、Markdownに書かれたままのパスとページのデータを渡し、返ったURLを使う |
| 絶対URL（`https://…`） | そのまま使う |
| 相対パス・`src` のページ | `src` のURLを基準に解決する（`images/a.png` → mdファイルと同じ場所の `images/a.png`） |
| 相対パス・`md` のページ | `baseUrl` を基準に解決する。`baseUrl` 未指定時は組み込み先ページのURLを基準にする（組み込み先の `<base>` は使わない） |

Markdown内にHTMLで書いた画像（img の src・srcset、picture の source の srcset、input type="image" の src、SVG の image の href）も同じ順で決める。srcset はブラウザと同じ規則で候補に分ける（URLの中のカンマはURLの一部として扱う）。`imageResolver` が返す `blob:` のURL（利用側が認証付きで取得した画像）も画像に使える。`imageResolver` が例外を投げた画像は読み込まず、コンソールに警告を出す。srcset の候補では、その候補だけを除き、残りの候補を使う。

ページのデータの `thumbnail`（子ページ一覧のカードの画像。本書 5.4）も、そのページの本文の画像と同じ順で決める（`imageResolver` には `thumbnail` に書かれたままの値とそのページのデータを渡す。相対パスは、そのページが `src` のページなら `src` の場所、それ以外は `baseUrl` を基準にする）。決めたURLは本文の画像と同じサニタイズの規則で確かめ、本文で使えないURL（`javascript:` など）は使わない。

非公開S3では、署名付きURLの `src` を基準に相対パスを解決すると署名の部分が外れ、画像を表示できない。そのため非公開S3では `imageResolver` で利用側のAPI（例：`/api/manual/image?path=画像のパス`）を経由させ、利用側で画像ごとに署名付きURLを発行する。

Markdown内のリンク（a、area、SVG の a。SVG の a の xlink:href も含む）は、クリックしたときに次のように動く。上から順に判定し、最初に当てはまる動作をする。リンク先はブラウザと同じ読み方で判定する（前後の空白・制御文字と、途中のタブ・改行を除き、`\` は `/` と同じに扱う）。

| リンク先 | 動作 |
| --- | --- |
| `?page=ID`、`?page=ID#見出しID`（`urlParam` を変えた場合はその名前） | 本ライブラリ内でそのページに切り替える。`#見出しID` があれば切り替えた後にその見出しへスクロールする |
| `#見出しID` | ページ内目次のクリックと同じ動作をする（本書 5.5） |
| 相対パスで、解決後のURLがいずれかのページの `src` と一致する（どちらもクエリと `#` 以降を除いて比較） | 本ライブラリ内でそのページに切り替える（`[ログイン方法](login.md)` のような書き方に対応）。`#見出しID` があれば切り替えた後にその見出しへスクロールする |
| 上記以外の相対パス | 画像の相対パスと同じ基準（`src` または `baseUrl`）で解決したURLへ移動する。`imageResolver` は使わない |
| 組み込み先ページとオリジンが異なるURL | 新しいタブで開く。オリジンは組み込み先ページのURLで比べる（組み込み先の `<base>` は使わない） |
| 組み込み先ページとオリジンが同じ絶対URL | そのURLへ移動する |

### 5.4 表示機能

パンくず・サイドバー・ページ内目次・前後のページは、すべて受け取ったデータと本文から自動生成する。置く場所は本書 6。

| 機能 | 生成元 | 内容 |
| --- | --- | --- |
| パンくず | `parentId` をたどる | ツールバーに、最上位から現在のページまでを並べる。上の階層を小さく1行目に（例：はじめに › ログイン方法）、現在のページの名前を2行目に出す。上の階層のないページでは名前だけを出す。上の階層はクリックでそのページに切り替える |
| サイドバー | 親子関係 + 並び順 | 上に「ページ」の見出しを置き、その下にページ階層のツリーを表示する。現在のページを強調表示する。子を持つページは開閉でき（その場で子ページの並びの高さを0.2秒で伸ばして開き、縮めて閉じる。開閉ボタンの矢印もその向きに回る）、現在のページまでの階層は開いた状態で表示する。ページを切り替えて、閉じていた階層が開くときも、開閉ボタンと同じように伸ばして開き、矢印を回す（何階層も閉じていたときは、いちばん外の並びが中の並びごと伸びる）。最初の表示と、`pages`・`fetch` の変更で一覧を読み直したときは、伸ばさずに開いた状態で表示する |
| ページ内目次 | 本文の h2・h3 | 上に「目次」の見出しを置く。クリックで該当見出しへなめらかにスクロールする（URLへの反映は本書 5.5）。スクロールしている間は、通り過ぎる見出しではなく、選んだ見出しを強調する。利用者がホイール・指・スクロールのキー（↑↓・PageUp・PageDown・Home・End・Space）でスクロールすると、その時点から通常の決め方に戻る。狭い表示幅の折りたたみの目次は、閉じてからスクロールする。着いたら（スクロールが止まったら）、その見出しの文字と下線（3px）を強調色（`--mpv-color-accent`）にして、1.5秒ほどで元に戻す。この間、見出しに part `target-heading` を付ける（本書 5.8）。組み込み先が `::part(target-heading)` で動きを消したとき（`animation: none` など）も、1.5秒ほどで外す。動きの長さを変えたときは、その動きが終わったときに外す。途中で利用者がスクロールしたときと、ページを切り替えたときは付けない。もう着いている見出しを選び直したときも付ける。読んでいる見出し（スクロールの基準の表示範囲の上端から 16px 下の位置を最後に通り過ぎた見出し。高さ未指定のときは、上に残るツールバーの下端を表示範囲の上端とする。目次・リンク・検索で移動した見出しは上端に来るため、その見出しになる。いちばん下までスクロールしたときは、表示範囲にある最後の見出し。ただし、目次・リンク・検索で移動した見出しが、本文が短い・最後のほうの見出しであるなどの理由で上端まで来られないときは、それ以上下へスクロールできず、その見出しが表示範囲にある間は、その見出しとする。上へスクロールして下へスクロールできるようになるか、その見出しより後ろの見出しが上端の位置を通り過ぎると、通常の決め方に戻る）を、スクロールに合わせて強調する。h2 はすべて並べ、h3 は読んでいる見出しが属する h2 の分だけ並べる（最初の h2 より前の h3 は常に並べる）。h2・h3 がないページでは目次の場所ごと表示しない |
| 本文 | `md` または `src` | GFM（表・取り消し線・タスクリスト・自動リンク）に対応したMarkdownをHTMLに変換し、サニタイズして表示する |
| 見出しへのリンク | 本文の h2〜h6 | 本文の各見出し（h2〜h6。ページ名の h1 と子ページ一覧は除く）の文字の右に、その見出しへのリンクをコピーするボタンを置く。ボタンは、見出しにマウスを置いている間と、Tab でボタンに移っている間と、コピーした後の1.5秒ほどだけ見え、ほかのときは見えない（場所は取るが、見出しの高さは変えない）。マウスを置けない画面（タッチ）では、いつも薄く出す。押すと、組み込み先の URL のクエリ `page`（`urlParam`）を今のページのIDに、`#` をその見出しのIDにした URL（ほかのクエリはそのまま。見出しのIDは `%` の形に符号化する）をクリップボードにコピーする。クリップボードの API が使えない・断られた場合は、ブラウザの古いコピーの命令で試す。コピーしたら、ボタンをチェックの印にし、ボタンの右（右に余地がなければ左）に「リンクをコピーしました」を1.5秒ほど出し、読み上げにも同じ文言を伝える。どちらの方法でもコピーできなければ「コピーできませんでした」を出す。ページは動かさず、URL と履歴も変えない。ボタンの読み上げ用の名前は「「（見出し）」へのリンクをコピー」。見出しの文字は変えないので、目次と検索には影響しない。見出しがリンクの中にある場合も、押すとコピーだけを行い、リンク先へは移らない。`urlParam` に `false` を指定した場合は、その URL を開いてもそのページにならないため、ボタンを置かない |
| 画像の拡大 | 本文の画像 | 本文の画像のうち、元の大きさより小さく出ているもの（本文の幅に合わせて縮んだもの、HTML の `width`・`height` で小さくしたもの）は押せる。押せる画像の上ではカーソルが虫眼鏡になり、Tab で移れ、読み上げでは「画像を拡大：（代わりの文字）」のボタンになる（本文に書かれた `tabindex`・`role`・`aria-label` はそのまま使う）。ほかの見た目は変えない。元の大きさで出ている画像、リンク・ボタン・`label`・`summary` の中の画像（押すとそのリンクやボタンが動く）、`usemap` の画像は押せない。押せるかどうかは、画像を読み込んだときと、出ている大きさが変わったとき（本文の幅が変わったときなど）に決め直す。押すと（Enter・Space でも）、画面全体を暗くし、その画像（本文に出ているのと同じもの。`srcset` のときはブラウザが選んだもの）を、元の大きさか、画面に収まる大きさに縮めて真ん中に出す。下に代わりの文字（alt）を出し（ないときは出さない）、右上に閉じるボタンを出す。開くと閉じるボタンに移る。閉じるボタン・Esc キー・画像の外を押すと閉じ、画像を押しても閉じない。閉じると元の画像に戻る。Esc は拡大を閉じることだけに使い、組み込み先には使われたキー（`defaultPrevented`）として届く（組み込み先が Esc で閉じるヘルプのパネルなどは閉じない）。開いている間は、後ろのページをホイールでスクロールしない（Ctrl とホイールでのページの拡大はそのまま）。ページが切り替わったとき・要素がページから外されたときは閉じる。画像は先に読み込んでおく（遅れて読み込むと、目次で移った見出しの位置が、途中で読み込まれた画像の高さの分だけずれるため） |
| 子ページ一覧 | 親子関係 + 並び順 + `description` + 子ページの本文の h2 | `md` も `src` もないページの本文の場所に、直下の子ページをサイドバーと同じ順に並べる。最初は表の形（1行に1ページ。上に「ページ」「内容」の見出しの行を置き、名前・`description`・数の列の位置を各行でそろえる）で出し、ツールバーのボタンでカードの形に切り替えられる。選んだ形は、ほかのページに切り替えても保つ。ページの名前はツールバーに出し、本文の h1 は読み上げ用として画面には出さない。各ページには子ページの名前、`description`（表では2行、カードでは3行を超える分は省略）、章の数（本文を `md` で渡したページの h2 の数。「N章」）または子ページの数（`md` も `src` もないページ。「Nページ」）を出す。`src` のページは一覧のために本文を取得せず、数を出さない。数を数えるときは画像・動画・音声を読み込まず、`imageResolver` も呼ばない。カードの形では、`thumbnail` を指定したページのカードの上端に、その画像を横長（縦横比 16:9。比率の違う画像ははみ出た分を切る）で出す（解決の規則は本書 5.3）。画像は画面に近づいたときに読み込み、代わりの文は付けない（名前がその下に出るため）。読み込めなかった画像は取り除き、`thumbnail` のないページと同じカードにする。表の形では画像を出さず、読み込まず、`imageResolver` も呼ばない。マウスを置くと、表では行に背景を付けて名前を強調色にし、カードでは枠を強調色にして背景を付ける。クリックでそのページに切り替える（本書 5.5 のページの切り替え）。子ページがないページは本文を空にする |
| 前後のページ | 親子関係 + 並び順 | 本文の最後（子ページの一覧のページでは一覧の下）に、サイドバーの順（上から。子ページは親の直後）で前と次のページへのリンクを出す。子ページの一覧のページも順に含まれ、そこからも前後へ行き来できる。各リンクには「前へ」「次へ」と、そのページの位置（最上位から順のページ名）を出す。位置が長いときはリンクの中で折り返し、省略しない。最初・最後のページでは片方だけを出し、読み込み中・エラー・「ページが見つかりません」の表示では出さない。クリックでそのページに切り替える（本書 5.5 のページの切り替え） |
| 注意・ヒントの囲み | 本文の引用 | 引用（`>`）の1行目が `[!NOTE]`・`[!TIP]`・`[!IMPORTANT]`・`[!WARNING]`・`[!CAUTION]` だけ（大文字・小文字は問わない。前後の空白は可）の場合、その引用を色付きの枠にする（GitHub の Markdown と同じ書き方）。枠の上に種類の見出し（補足・ヒント・重要・注意・警告。言語は本書 5.10）とアイコンを出し、印（`[!NOTE]` など）は本文から除く。2行目以降はふつうの Markdown（段落・箇条書き・表・リンクなど）として表示する。枠は左の線と、うすい色の背景で、色は種類ごとに本書 5.8 の CSS 変数で変えられる（初期値は青・緑・紫・黄土・赤）。知らない種類、印の行にほかの文字がある場合、印を太字などで書いた場合、引用の中の引用は、ふつうの引用のまま表示する |
| 検索 | `title` + `description` + 本文の見出しと文 | ツールバーの検索欄に入力すると、検索欄の下に重ねて一致した結果を並べる（最大50件）。ページ名・`description` の一致、見出しの一致、本文の一致の順に、同じ順の中はサイドバーと同じ順に並べる。各結果には、そのページの位置（最上位から順のページ名。例：代理店 › ダッシュボード）を出し、同じ名前のページを区別できるようにする。本文の一致は、その文が属する見出しと、一致した部分の前後の文を出す。一致した部分に印を付ける。全角・半角と大文字・小文字は区別しない。空白で区切った語は、すべてを含むものだけを一致とする。結果のクリックでそのページ（見出し・本文の一致はその見出しの位置）に切り替える（本書 5.5 のページの切り替え）。↑↓ キーで結果を選び（最初は先頭。端からは反対の端へ回る）、Enter で選んだ結果を開く。結果を開くと、検索欄を空にして結果を閉じ、検索欄から離れる。Esc で入力を消して結果を閉じる（入力が空のときは検索欄から離れる）。結果の外をクリックすると結果を閉じ、検索欄に戻ると同じ結果を出す。入力欄の外で「/」キーを押すと検索欄に移る（修飾キーとの組み合わせ、組み込み先を含む入力欄の中、中の見えないカスタム要素の中、ページがないときなど検索欄を使えないときは何もせず、キーもそのまま組み込み先に渡す）。本文の見出しと文は、検索欄に入ったとき（入力したときを含む）から、画面を止めないように少しずつ、サイドバーの順に読む。読み終えるまでは、ページ名・`description` はすべてのページを、見出しと本文は読み終えたページだけを対象にして結果を出し、結果の下（一致がまだない場合は結果の代わり）に「検索しています…」と出して、読み進めるにつれて結果を更新する。結果が増えても、選んでいた結果は選んだままにする。要素が画面から外れている間は読まず、戻ると続きから読む。すべてのページを読み終えても一致がない場合は「「入力した語」に一致するページはありません」と出す。本文を `src` で渡したページは検索のために本文を取得せず、ページ名と `description` だけを対象にする。本文を探すときは画像・動画・音声を読み込まず、`imageResolver` も呼ばない。注意・ヒントの囲みの見出し（補足・注意など）は本ライブラリの文言で、言語によって変わるため、検索の対象にせず、抜き出す文にも含めない。ページ一覧が変わったときは結果を作り直す |

見出しIDは、本文をサニタイズした後に付ける。IDは見出しの文字列から作り、空白は `-` に置き換える。表示領域の中にすでに同じIDがある場合（同じ文字列の見出しが続く場合、本文のHTMLに同じidがある場合など）は、末尾に `-2`、`-3` … と、重ならない番号まで進めて付ける。URLとリンクの `#` 以降は、デコードしてから見出しIDと比べる（デコードできない場合はそのまま比べる）。

### 5.5 URLへの反映とスクロール

| 操作 | URL・履歴 | スクロール |
| --- | --- | --- |
| 最初に表示する | 書き換えない | URLの `#` が本文の見出しIDと一致する場合だけ、その見出しへスクロールする |
| ページを切り替える（サイドバー・パンくず・本文内リンク・子ページ一覧・前後のページ・検索の結果・`currentId` の変更） | 組み込み先ページのURLのクエリ `page` を切り替え先のIDにし、`#` を外して（リンクに `#見出しID` がある場合はそれを付けて）、ブラウザの履歴に追加する。他のクエリはそのまま残す。画面は再読み込みしない | `#見出しID` があればその見出しへ、なければ本文の先頭へスクロールする |
| 表示中のページをもう一度選ぶ | リンクに `#見出しID` がある場合は、次の行（ページ内目次のクリック）と同じ。ない場合は変えない | `#見出しID` があればその見出しへ、なければ本文の先頭へスクロールする |
| ページ内目次・本文内の `#見出しID` のリンクをクリック | URLの `#` をその見出しIDにする。履歴は追加せず、現在の履歴を書き換える。組み込み先が保存している `history.state` はそのまま残す | その見出しへスクロールする（ページ内目次からは、なめらかに。本書 5.4） |
| ブラウザの戻る・進む | 変えない。URLの `page` の値（`page` がない場合は、最初の表示で開いたページのID。そのページが今の一覧になく、最初の表示の後に `pages`・`fetch` の変更で一覧を読み直している場合は本書 5.1 の3で決まるページのID。署名付きURLの期限切れで同じ一覧を取得し直したことは、一覧の読み直しに数えない）を表示中のページと比べ、異なるときだけそのページに切り替える。存在しないIDの場合は「ページが見つかりません」を表示する。同じ場合は描画し直さない | ページを切り替えた場合は、URLの `#` が見出しIDと一致すればその見出しへ、なければ本文の先頭へスクロールする。切り替えない場合はスクロールしない |
| `?page=ID` 付きのURLを開く | 本書 5.1 のとおり | 「最初に表示する」と同じ |

戻る・進むで比べる「表示中のページ」は、最後に決めたページのIDとする。「ページが見つかりません」を表示している場合は、そのとき決めた（存在しない）IDとする。

URLの `#` と比べるのは本文の見出しのIDだけとする（組み込み先自身のアンカーで本文の中へスクロールしないため）。本文内の `#ID` のリンクは、見出し以外の要素のIDにも移動する。

本文の先頭へのスクロールは、表示領域の高さによって次のように動く（高さの扱いは本書 6）。「スクロールの基準」は、実際に縦にスクロールする最も近い祖先要素（overflow-y が visible・clip 以外で、中身が枠より長い要素）で、なければ画面とする。overflow-x: hidden のラッパーのように、overflow が指定されていてもスクロールしない要素は基準にしない。body は、その overflow が画面に引き継がれない場合（html の overflow が visible 以外の場合）だけ基準にする。

| 高さ | 動作 |
| --- | --- |
| 組み込み先が指定していない | 表示領域の上端がスクロールの基準の上端より上にある場合だけ、スクロールの基準をスクロールして上端を合わせる |
| 組み込み先が指定している | 本文の場所の中を先頭までスクロールする |

高さを指定していない場合、見出し（本文内の `#ID` のリンクで移動する要素を含む）へのスクロールでは、上に残るツールバー（本書 6）に隠れないよう、ツールバーの下端から 8px 下にその上端を合わせる。組み込み先が `--mpv-top-offset`（固定ヘッダーの高さ）を指定した場合は、ツールバーがその分だけ下に残るので、見出しもその分だけ下に合わせる。スクロールの基準（画面の場合は html）に `scroll-padding-top` があれば、ブラウザがその分を空けるので、`--mpv-top-offset` からその分を差し引く（二重にずらさない。`scroll-padding-top` の方が大きい場合は、その指定どおり空く）。本文の先頭へのスクロールでも、表示領域の上端をスクロールの基準の上端から `--mpv-top-offset` だけ下に合わせる。

クエリの名前は `urlParam` で変えられる（組み込み先がページ送りなどで `page` を使っている場合）。`urlParam` に `false` を指定した場合（同じ画面に2つ以上置く場合、組み込み先がURLの `#` で画面を切り替えている場合など）は、この表のURLの読み取り・書き換えと履歴の追加、戻る・進むへの対応をすべて行わない。スクロールとページの切り替えは同じように動き、本文内の `?page=ID` のリンクはクエリ名 `page` で判定する。

### 5.6 タグと new の使い方

| 書き方 | 内容 |
| --- | --- |
| `<md-pages-viewer>` タグ | スクリプトを読み込むとタグが使えるようになる。文字列で渡せるオプションは属性で渡す。配列・関数・オブジェクト（配列の `pages`、`imageResolver`、`fetch`、`texts`）と `styles` はJSで要素のプロパティに設定する。タグが使えるようになる前に設定したプロパティも、使えるようになった時点で反映する。`pages` が設定されるまでは何も表示しない。`fetch` を使う場合は、`pages` を属性ではなくJSのプロパティで、`fetch` より後に設定する |
| `new MdPagesViewer(要素またはセレクタ, オプション)` | 指定した要素の中身を `<md-pages-viewer>` に置き換える。作った要素にオプションをすべて設定してから指定した要素に入れる。戻り値は作った要素を `element` として持ち、表示後のオプションの変更はその要素のプロパティに設定する。作った要素の高さは指定した要素の高さに合わせる（指定した要素に高さがなければ本文に合わせて伸びる）。セレクタに合う要素がない場合は例外を投げる。描画の処理はタグと共通 |

表示した後に属性・プロパティを変更した場合は、その内容で描画し直す。続けて行われた変更は、まとめて1回描画する。

| 変更したもの | 動作 |
| --- | --- |
| `pages`・`fetch` | ページ一覧を読み直し、保持した本文を捨てる。表示中のページが新しい一覧にあればそのページを表示する。なければ本書 5.1 の2・3で決まるページを開き、URLの `page` をそのIDに書き換える（履歴は追加せず、現在の履歴を書き換える） |
| `currentId` | 設定すると（同じ値を設定し直した場合も）、そのページが表示中でなければ切り替える（本書 5.5 のページの切り替え）。サイドバー・パンくず・本文内リンクでページを切り替えても、`currentId` の値は変わらない |
| `pages` と `currentId` を同時に | 新しい一覧を読み込んだ後に `currentId` のページを開く（本書 5.5 のページの切り替え）。そのページが新しい一覧にない場合は「ページが見つかりません」を表示する |
| `imageResolver`・`baseUrl` | 表示中のページの本文を描画し直す |
| `urlParam` | 次の操作から新しい名前でURLを読み書きする |
| `styles` | 描画し直さずに、すぐ見た目に反映する |
| `locale`・`texts` | 画面の文言（本書 5.10）をすぐ新しいものにする。表示中のページ・スクロール位置・URL・開いている検索結果は変えない。本文を表示している間は、囲みの見出しのために本文を描画し直す。読み込み中・エラーの表示も、表示したまま文言だけを変える |

- `pages`・`fetch` の変更で一覧を取得している間（取得に失敗して再読み込みボタンを出している間を含む）に `currentId` の変更や戻る・進むがあった場合は、新しい一覧が届いてから、その一覧で開くページを決める。両方があった場合は、後から行われた方に従う。ページが変わらない戻る・進む（組み込み先自身の `#` のリンクなど）は数えない。`pages`・`fetch` がさらに変わっても、要素を取り除いて入れ直しても、これらの指示は残す
- 同じオプションを属性とプロパティの両方で設定した場合は、後から設定した方を使う
- 同じページでスクリプトが2回読み込まれた場合は、2回目のタグ登録を行わない
- 要素をページに入れたときに戻る・進むの監視を始め、取り除いたときに止める。一覧の取得中に取り除いた場合は、届いた一覧を使わず（組み込み先のURL・履歴を変えない）、ページに入れ直したときに取得し直す

### 5.8 スタイル

- 表示はShadow DOMの中に作り、CSSもその中に入れる。組み込み先のCSSのセレクタは中に効かず、本ライブラリのCSSは組み込み先に効かない
- CSSはJSファイルに含めて配布する。組み込みはスクリプトの読み込みだけで済む。CSSは Shadow DOM に構築済みのスタイルシート（adoptedStyleSheets）として入れ、組み込み先の CSP の style-src に 'unsafe-inline' がなくても効くようにする
- 本ライブラリの中の重なり順（z-index）は表示領域の中だけで比べ、組み込み先の要素（固定ヘッダーなど）と比べない。ただし、本文の画像の拡大（本書 5.4）だけは、ブラウザの最前面（top layer。モーダルの `dialog`）に出し、組み込み先の固定ヘッダーなどを含む画面全体を覆う。組み込み先が要素をはみ出しを隠す枠（`overflow: hidden`・`transform` のあるパネルなど）の中に置いても同じ
- 表示の向きは左から右とし、組み込み先の direction（RTL）は引き継がない
- 組み込み先から引き継ぐのは、文字色とフォントの種類（`color`・`font-family`。どちらもCSS変数で上書きできる）と、表示・操作の可否（`visibility`・`pointer-events`。組み込み先が親要素を隠したときに本ライブラリも隠れるようにするため）と、ページの言語（要素から上にたどって最初に見つかった `lang`。Shadow DOM の外側もたどる。初期値に戻すと言語も消えるため、表示領域の中で指定し直す。要素をつないだときと、ページを表示するたびに読み直す。どこにも `lang` がなければ指定しない）
- 見出し・表のセル・ページ一覧と目次の項目・子ページ一覧の名前と説明文・前後のページの名前・検索の結果のページ名と見出しは、言語が日本語のとき、文節の切れ目で折り返す（「必須」「店舗コード」のような短い言葉を途中で折らない。CSS の `word-break: auto-phrase`）。本文の段落は、文節で折ると右端のでこぼこが目立つため、通常の折り返しのままにする。この折り返しに対応していないブラウザ（Safari・Firefox）と日本語以外の言語では、通常の折り返しになる

- それ以外の、親から引き継がれる値（行の高さ・文字の大きさ・文字間隔・揃え位置・改行の扱いなど）は、表示領域の外枠で初期値に戻す。大きさは `px` と `em` で指定し、組み込み先の `html` の文字の大きさに左右されないようにする
- Markdown内の `<style>` タグは本書 5.9 で除去し、本ライブラリの画面に効かないようにする
- 本文に書かれた `style` 属性が本文の場所の外に表示されないよう、本文の場所を中の要素の配置（`position: fixed` を含む）の基準にし、外にはみ出す部分を切り取る。幅の広い表は、表を囲む枠の中だけで横にスクロールする（本文全体は横にスクロールしない。表は表のまま読み上げられる）。表以外の幅の広いものは、本文の場所の中で横にスクロールする

### 5.9 セキュリティ

DBやS3の内容をそのまま表示するため、Markdownを変換したHTMLは、画面に入れる前に必ずDOMPurifyでサニタイズする。サニタイズは、パスを解決したのと同じ要素の木に対して行い、文字列に戻して解析し直さない（解析し直すと形が変わるHTMLで、サニタイズ後に別の要素が現れないようにするため）。次のものを除去する。

| 除去するもの | 理由 |
| --- | --- |
| scriptタグ、`onclick` などのイベント属性、`javascript:` で始まるURL | スクリプトの実行を防ぐ |
| `<style>` タグ | 本ライブラリの画面に効くため |
| `<dialog>` タグ、`popover`・`popovertarget`・`command`・`commandfor`・`interestfor` などの属性 | 画面の最前面（トップレイヤー）に出て、組み込み先の画面を覆えるため |
| `<slot>` タグ、`part`・`exportparts` 属性 | 組み込み先の子要素や `::part()` のCSSが本文に入るため |
| `poster`・`background` 属性、SVG の `<feImage>`、画像を読み込むCSS（`url()` など）またはCSSのエスケープ（`\`）を含む `style` 属性、SVG の `fill`・`stroke`・`mask`・`filter`・`clip-path`・`marker`・`cursor` 属性で外部を参照する `url()`（文書内の `#ID` の参照は残す） | `imageResolver` と相対パスの規則（本書 5.3）を通らずに画像を読み込むため |
| `<form>` タグ（中の入力欄やボタンは残す） | 送信すると、入力値が別の場所へ送られ、組み込み先のタブが別のページへ移るため |
| `data-mpv-` で始まる属性、`mpv-` で始まるクラス名（大文字小文字を区別しない） | 本ライブラリの部品やページ切り替えのリンクを装えないようにするため。本ライブラリが使う目印はサニタイズの後に付ける |

CSP で Trusted Types を強制するページ（`require-trusted-types-for 'script'`）でも動かす。サイドバーなどの部品は文字列からHTMLを作らずに組み立てる。本文だけは、Markdownを変換した文字列を実行も読み込みも起きない template 要素に入れるため、`md-pages-viewer` という名前のポリシーを1つ使う。`trusted-types` ディレクティブで許可する名前を限定しているページでは、組み込み先がこの名前を追加する。許可されていない場合は、本文の場所に「読み込めませんでした」と表示してコンソールに警告を出し、サイドバーなどはそのまま動かす。

`styles`（本書 5.8）のCSSは組み込み先が書いたものとしてそのまま使い、サニタイズしない。表示領域の中のすべての部品（ツールバー・検索欄・サイドバーを含む）に効き、部品を隠す・別の部品に見せる・`url()` で外部の画像を読み込むこともできるため、組み込み先は、利用者が入力した文字列やDBの値など、組み込み先が書いていないCSSを渡さない。

### 5.10 画面の文言

本ライブラリが画面に出す文言（ボタン・見出し・検索欄・読み込み中やエラーの表示・読み上げ用の名前など）は、`locale` で言語を選び、`texts` で1つずつ置き換えられる。本書のほかの節に書いた文言（「ページ」「目次」「読み込み中…」など）は日本語のときのもの。

- 組み込みの言語は、日本語（`ja`）・英語（`en`）・中国語の簡体字（`zh-CN`）・繁体字（`zh-TW`）・韓国語（`ko`）。`locale` を指定しないとき、空のときは日本語
- `locale` は言語タグで書く。大文字・小文字と、`-` の代わりの `_` は区別しない。地域などの付いたタグはその言語にする（`en-US` は `en`、`ko_KR` は `ko`）。中国語は、繁体字のタグ（`zh-Hant`・`zh-TW`・`zh-HK`・`zh-MO` を含むもの）を `zh-TW`、それ以外（`zh`・`zh-Hans`・`zh-SG` など）を `zh-CN` にする。組み込みにない言語（`fr` など）と文字列でない値は、日本語にしてコンソールに警告を出す
- `texts` は、下の表のキーと文言のオブジェクト。書いたキーだけを置き換え、ほかは `locale` の言語の文言を使う。数・検索語・ページ名を出す文言は、それを受け取って文言を返す関数で書く（例：`chapters: (n) => '全' + n + '章'`）。表にないキー、文字列のはずのところに文字列以外、関数のはずのところに関数以外を書いたものは、警告を出して使わない。関数が例外を投げたときと文字列を返さなかったときは、警告を出して、その回は `locale` の言語の文言を使う。オブジェクトの中身を書き換えても反映しないため、変えるときは新しいオブジェクトを設定する
- ページのデータ（`title`・`description`・本文）は組み込み先のもので、本ライブラリは訳さない。言語を切り替える場合は、組み込み先が `locale` と一緒に、その言語のページのデータを `pages` に渡す。言語を切り替えるボタンなどは本ライブラリには置かず、組み込み先が作る

## 6. 画面設計

本ライブラリの表示領域の中の構成。表示領域の幅は組み込み先が置いた要素の幅に従う。高さは、組み込み先が指定しない場合は本文の長さに合わせて伸び、スクロールの基準（本書 5.5）をスクロールしても、ツールバーは見える範囲の上端に、サイドバーと目次はその下に残る。overflow-x: hidden のラッパーのように、スクロールしない祖先要素に overflow が指定されていても同じ。組み込み先が高さを指定した場合は、ツールバーの下で、サイドバー・本文・目次がそれぞれの中でスクロールする。

組み込み先の画面の上に固定ヘッダーがある場合は、組み込み先がその高さを CSS 変数 `--mpv-top-offset`（本書 5.8）で渡す。高さを指定していない場合に、ツールバーは見える範囲の上端からその分だけ下に、サイドバーと目次（狭い表示幅で開いたサイドバーを含む）はその下に残り、縦の長さもその分だけ短くする。止まっている状態では位置を変えない（ツールバーが元の位置より下に押し下げられない）。スクロールしない祖先要素に overflow がある場合（列を手で動かす場合）も同じ。ページ内目次の「読んでいる見出し」を決める線も、ツールバーと固定ヘッダーの下に合わせる。組み込み先が高さを指定した場合は使わない。指定しなければ、これまでどおり見える範囲の上端に残る。

| 場所 | 内容 |
| --- | --- |
| 上 | ツールバー。左端にサイドバーを開閉するボタン、続けてパンくず、検索欄を置く。右端には、h2・h3 があるページではページ内目次を開閉するボタンを、子ページ一覧のページでは表とカードを切り替えるボタン（今と違う形の名前。「カード表示」「一覧表示」）を置く |
| 左 | サイドバー（上に「ページ」の見出し、その下にページ階層のツリー） |
| 中央 | 本文（`md` も `src` もないページでは子ページの一覧）と、その最後に前後のページ（本文が長いときは、最後までスクロールすると見える）。読み込み中・エラーの表示もここに出す |
| 右 | ページ内目次（上に「目次」の見出し）。h2・h3 がないページでは表示せず、その分本文を広げる |

サイドバーと目次は、ツールバーの左端・右端のボタンで閉じられ、閉じた分だけ本文を広げる。開くときも同じ場所の同じボタンを押す（ボタンの矢印の向きと名前が「閉じる」「開く」で変わる）。閉じた状態は、ページを切り替えても保つ。閉じるときは列の幅を0.2秒で縮め、開くときは同じ時間で広げる（本文もそれに合わせて広がり、狭まる）。その間、列の中の文字は折り返さず、はみ出た分を隠す。

開閉の動き（この節の列の幅、狭い表示幅のサイドバーの移動と後ろの暗さ、サイドバーの子ページの並びの高さ（本書 5.4））は、利用者が OS やブラウザで動きを減らす設定（`prefers-reduced-motion: reduce`）にしている場合は付けず、すぐに切り替える。ページ内目次で選んだ見出しへのスクロール（本書 5.4）も、この設定のときはなめらかにせず、すぐに移る。着いた見出しを示す動きも付けない。

高さの指定の有無は、doctype のないページ（互換モード）でも同じに判定する。

本ライブラリの表示幅が768px未満のときは次の配置にする。表示幅は画面の幅ではなく、組み込み先が置いた要素の幅で判定する。

| 場所 | 内容 |
| --- | --- |
| 上 | ツールバー。サイドバーを開閉するボタン・パンくず・検索欄を置き、ページ内目次を開閉するボタンは置かない |
| サイドバー | ツールバーの左端のボタンで開き、ツールバーの下に、本文の上に重ねて表示する。開くときは要素の左端から0.2秒で滑り出し、閉じるときは同じ時間で左端へ戻る。動いている間も要素の左端より外（組み込み先の画面）には出さない（切り口は要素の左端に固定し、動かすのはページ一覧の位置だけにする。切り口も一緒に動かすと、ブラウザによっては2つの動きが別々に描かれてずれ、外にはみ出すため）。後ろの本文は、開くと徐々に暗くなり、閉じると徐々に戻る。高さ未指定でスクロールした後でも、見える範囲に開く。ページ（検索の結果を含む）を選ぶか、同じボタンか、外側（組み込み先の画面を含む）をクリックすると閉じる。組み込み先が本ライブラリを閉じた Shadow DOM の中に置いた場合も同じ |
| 本文の上 | ページ内目次。折りたたんだ状態で表示し、クリックで開く |

## 7. 処理フロー

1. 利用側のページでスクリプトを読み込む。`<md-pages-viewer>` タグが使えるようになる
2. 利用側がタグを置く、または `new MdPagesViewer()` でタグを作る。タグが使えるようになる前に設定されたプロパティを反映する
3. `pages` がURLならページ一覧を取得し、配列ならそのまま使う
4. 本書 4 のルールで階層と並び順を組み立てる
5. 最初に開くページを決める（本書 5.1）
6. ツールバーのパンくずとサイドバーを描画する
7. 本文を用意する。`md` ならそのまま使い、`src` なら取得する（保持した本文があればそれを使う。失敗時は本書 5.2）。どちらもなければ子ページの一覧（本書 5.4）を作って見出しIDを付けて本文の場所に入れ、9 に進む
8. MarkdownをHTMLに変換し、画像・リンクのパスを解決し（本書 5.3）、サニタイズした後に見出しIDを付けて本文に入れる
9. 本文の h2・h3 からページ内目次を作り、本文（子ページの一覧）の最後に前後のページを出す
10. 本書 5.5 の「スクロール」の列に従ってスクロールする。最初の表示とページの切り替え後で動作が異なる
11. ページが切り替えられたら（`currentId` の変更を含む）、URLの `page` を更新して履歴に追加し（本書 5.5）、6 から繰り返す
12. ブラウザの戻る・進むでは、本書 5.5 の比べ方で表示中のページと異なるときだけ、そのページで 6 から繰り返す
13. 本文をスクロールするたびに、ページ内目次の読んでいる見出しと、並べる h3 を更新する（本書 5.4）
14. 検索欄に入ると、`md` のページの本文を少しずつ読み始める。検索欄に入力すると、ページ一覧の各ページ（本文は読み終えたページ）から結果を作って検索欄の下に並べ、読み進めるにつれて結果を更新する（本書 5.4）。結果が選ばれたら 11 と同じくそのページに切り替える

ライセンスはMITとし、著作権表示は「Copyright (c) 2026 Kota Kagatsume」とする。この表示とMITライセンスの全文を書いた LICENSE ファイルを、リポジトリ・npmパッケージ・GitHub Releases に含める。

| 方法 | 用途 | 読み込むもの | 準備 |
| --- | --- | --- | --- |
| CDN（jsDelivr / unpkg） | 基本の使い方 | `https://cdn.jsdelivr.net/npm/md-pages-viewer@1/dist/md-pages-viewer.js` を `<script>` で読み込む | npm公開で自動的に利用可能 |
| ダウンロード | 外部CDNに接続できない環境 | `md-pages-viewer.js` を自サーバーに置き、`<script>` で読み込む | GitHub Releasesにビルド済みファイルを添付 |
| npm install | Viteなどでビルドするプロジェクト | `md-pages-viewer` から `MdPagesViewer` を `import` する | npm公開のみ |

ビルドで作るファイル：

| ファイル | 内容 |
| --- | --- |
| `dist/md-pages-viewer.js` | `<script>` 用。読み込むとタグを登録し、`MdPagesViewer` をグローバルに置く |
| `dist/md-pages-viewer.mjs` | npm install 用（ESモジュール）。`import` するとタグを登録する。`MdPagesViewer` は名前付きで export する |

- どちらのファイルにも marked・DOMPurify・CSSを含める
- どちらのファイルもASCII文字だけで書き出す（日本語・中国語・韓国語の文言はエスケープする）。文字コードの指定なしで配られても、Shift_JIS などのページで文字化けしないようにするため
- npmパッケージを作るとき（`npm pack`・`npm publish`）は、先に自動でビルドする。ビルドを忘れても、`dist` のないパッケージや古い `dist` のパッケージが公開されないようにするため
- npmパッケージには、使い方を書いた README.md を含める
- CDNのURLはメジャーバージョン（`@1`）まで固定して案内する。機能追加・不具合修正は自動で反映され、書き方が変わる更新は反映されない
- どちらのファイルも先頭に、本ライブラリと、同梱する marked・DOMPurify の名前・著作権表示・ライセンス名をコメントで残す。圧縮しても消えない形のコメントにする
- marked のライセンス全文（MITライセンスと John Gruber の Markdown のライセンス）と DOMPurify のライセンス全文（Apache-2.0 を選ぶ）をまとめたファイルを、npmパッケージと GitHub Releases に含める

| 表示 | 開閉の動き | 狭い表示幅のサイドバーが、開くときも閉じるときも動いている途中があり、その間も要素の左端より外（組み込み先の画面）には出ず、後ろの暗さが途中の濃さを通る。動くのはサイドバーの位置だけで、切り口は動かない。広い表示幅のサイドバーと目次が、閉じるときは幅が縮み、開くときは押した直後から見えて幅が広がり、途中でサイドバーの文字が折り返さない。サイドバーで子ページを開閉すると、子ページの並びの高さが途中を通って伸び縮みし、開閉ボタンの矢印が回る。ページ名を押して閉じていた子ページが開くときも、高さが途中を通って伸び、矢印が回る。何階層も閉じていたときは、いちばん外の並びだけが伸び、中の並びは開いた状態で出る。最初の表示とページのデータの差し替えでは動かない。動きを減らす設定では動かずにすぐ開閉する |

開発はClaude Codeで以下の順に進める。

1. リポジトリ作成、ビルド設定
2. 表示コアの実装（描画、パンくず、サイドバー、目次、`src` 取得、画像・リンクのパス解決、サニタイズ、URLへの反映）
3. 素のHTMLで動くデモページとテスト
4. GitHubとnpmへ公開、GitHub Releasesにビルド済みファイルを添付
5. 実プロジェクト1つに組み込み、不足機能を洗い出す
